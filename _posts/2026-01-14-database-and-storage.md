## 데이터베이스 및 스토리지
데이터와 이를 담는 저장 시스템은 서로 조화를 이루어야 한다. 어떤 데이터베이스와 스토리지를 선택하느냐에 따라 시스템의 성능, 비용, 운영 난이도가 결정된다. 데이터 엔지니어는 다양한 데이터를 수집, 정제하여 신뢰할 수 있는 형태로 제공하며, 이러한 아키텍처의 기반이 바로 데이터베이스와 스토리지이다.

---

## Storage
스토리지는 데이터의 물리적인 저장 공간이다. 데이터 구조와 무관하게 파일을 저장하며, 목적에 따라 역할이 세분화된다.

### 1. 블록 스토리지
데이터를 고정 크기의 블록으로 나누어 저장한다. 주소를 통해 직접 접근하므로 랜덤 읽기 및 쓰기 속도가 매우 빠르다. 지연 시간에 민감한 데이터베이스 파일이나 로그 저장에 주로 사용된다.

### 2. 파일 스토리지
데이터를 파일과 디렉토리 구조로 저장한다. 경로를 통한 접근이 가능하여 관리가 쉽고 여러 서버에서 공유하기 적합하다. 단, 파일 수가 많아지면 관리가 복잡해질 수 있다.

### 3. 오브젝트 스토리지
데이터를 객체 단위로 저장하고 고유한 식별자로 조회한다. 계층 구조가 없는 평면 방식이라 대용량 확장성이 매우 뛰어나다. 정형 및 비정형 데이터를 원본 그대로 쌓아두는 데이터 레이크에 주로 활용된다.

---

## Database
데이터베이스는 데이터를 조직화하고 효율적으로 관리하기 위한 규칙과 구조를 제공하는 시스템이다.

### 1. 관계형 데이터베이스 (RDBMS)
데이터를 행과 열로 구성된 테이블 형태로 관리한다. 기본 키와 외래 키를 통해 테이블 간의 관계를 정의하고 조인 연산을 수행한다. 명확한 스키마를 요구하여 데이터의 일관성과 정확성을 강하게 보장한다. 데이터 구조가 명확하고 변경될 여지가 적은 시스템에 적합하다.

### 2. 비관계형 데이터베이스 (NoSQL)
스키마가 없거나 유연하여 구조 변경이 잦은 데이터에 적합하다. 복잡한 조인 연산 대신 키나 문서 기반으로 빠른 읽기와 쓰기를 지원한다. 대용량의 비정형 데이터 처리에 유리하며, 분산을 통한 시스템 확장이 용이하다.

## 데이터 저장 아키텍처의 진화
### 1. 데이터 웨어하우스
전통적인 의사결정 및 분석을 위해 구축된 시스템이다. 정형 데이터 분석에 뛰어나지만, 비정형 데이터의 폭발적 증가와 유연성 요구를 감당하기에는 비용과 구조적 한계가 존재했다.

### 2. 데이터 레이크
저렴한 오브젝트 스토리지를 활용해 원시 데이터를 그대로 저장하는 방식이다. 다양한 데이터 활용을 위한 유연성은 확보했지만, 트랜잭션 처리나 데이터 품질 관리가 어려워 방치된 데이터의 늪이 될 위험이 있었다.

### 3. 2계층 아키텍처
데이터 레이크에 원본을 저장하고 정제된 데이터를 데이터 웨어하우스로 이동시켜 분석하는 구조이다. 시스템의 단점을 상호 보완하려 했으나, 데이터 중복이 발생하고 파이프라인 운영 복잡도와 인프라 비용이 증가하는 부작용이 생겼다.

### 4. 데이터 레이크하우스
데이터 레이크의 저렴하고 유연한 저장 공간 위에 데이터 웨어하우스의 테이블 관리 및 트랜잭션 기능을 결합한 최신 아키텍처이다. 데이터의 복사나 이동 없이 단일 환경에서 분석과 머신러닝을 모두 안정적으로 수행할 수 있게 되었다.
